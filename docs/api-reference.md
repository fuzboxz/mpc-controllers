# MPC 3.10.1.8 script API reference

Every table, function and property a controller script can see on **MPC 3.10.1.8 (build 38fdde70994), Live III**,
with what we know about each. Generated by `tools/api_reference.py` from the table dump in
[mpc-launchpad-pro-mk3/docs/LUA-API-DUMP.md](https://github.com/fuzboxz/mpc-launchpad-pro-mk3/blob/main/docs/LUA-API-DUMP.md)
by [@fuzboxz](https://github.com/fuzboxz) (captured 2026-11-17 from inside a running script, depth 4).
Notes come from [FINDINGS](findings/FINDINGS.md) and [COMMUNITY](findings/COMMUNITY.md).

**Present is not the same as working.** A name here only means the table has it. Several functions error or do
nothing when called (see the notes); anything without a note is untested. Property values are what the dump
saw on an empty project; read and write them through `.value`, and most can be listened to with
`prop:listen(fn, deviceName)`.

`[i]` = an indexed table (all entries share the shape shown). `dev` = your device table.

## Device table (`dev`)

### `dev`
The device table, named after the script file. MPC calls the `Handle*` and `On*` functions; you define them.
- **Functions:** `HandleMIDICC`, `HandleMIDINoteOff`, `HandleMIDINoteOn`, `HandleMIDISysex`, `HandleTimer`, `OnLoad`, `OnUnload`, `ResetControls`
- **Sub-tables:** `clipMatrixAperture`, `mappings`, `midiOut`, `timer`

### `dev.midiOut`
`outputIndex` = order of the `output=` lines in the `.ini`. Sysex payload without F0/F7. Script-sent MIDI doesn't loop back through `mappings` (COMMUNITY C4).
- **Functions:** `SendMIDICC`, `SendMIDINoteOff`, `SendMIDINoteOn`, `SendMIDISysex`
